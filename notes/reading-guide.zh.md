# 如何一起读这份组合动作调研

更新：2026-11-19。这里给出阅读路线和问题框架；具体事实、版本、证据入口见[逐篇审计卡](papers.md)。审计不是复现，也不把待验证判断写成现成结论。

## 先把“组合”拆成不同问题

| 组合对象 | 核心问题 | 推荐入口 |
|---|---|---|
| 时间片段 | 前后能否连续、顺序是否正确、时长与边界由谁给定 | [Motion Graphs](papers.md#motion-graphs)、[TEACH](papers.md#teach)、[FlowMDM](papers.md#flowmdm) |
| 身体部位 | 同时做不同动作时，部位职责与整体协调是否一致 | [SINC](papers.md#sinc)、[STMC](papers.md#stmc)、[FrankenMotion](papers.md#frankenmotion) |
| 语义或生成分布 | 多个概念/先验如何共同作用，而不相互覆盖 | [PriorMDM](papers.md#priormdm)、[EnergyMoGen](papers.md#energymogen)、[DeMoGen](papers.md#demogen) |
| 人—物—场景 | 接触、可达、对象身份与阶段后状态能否持续一致 | [CHOIS](papers.md#chois)、[HIMO](papers.md#himo)、[COSMI](papers.md#cosmi)、[World2HOSI](papers.md#world2hosi) |
| 多主体 | 一个主体的动作是否约束另一个，主体数与协作对象如何处理 | [InterGen](papers.md#intergen)、[ReMoS](papers.md#remos)、[InterMask](papers.md#intermask)、[CORE4D](papers.md#core4d) |
| 可执行技能 | 运动参考如何被控制器执行，组合是否维持平衡和接触 | [ASE](papers.md#ase)、[MaskedMimic](papers.md#maskedmimic)、[CLoSD](papers.md#closd)、[Weave](papers.md#weave) |

这些是不同研究问题。一个工作可以拥有多个标签，但“使用了 diffusion”“输出长视频”“模型里有多分支”都不足以直接证明组合泛化。

## 第一轮：形成领域地图

先读经典片段/图方法，再看 TEACH → FlowMDM 的时间组合；用 SINC → STMC → FrankenMotion 理解空间职责、时间线与标注粒度。接着比较 PriorMDM、EnergyMoGen、DeMoGen：分别讨论先验复用、生成时分布组合和可重组概念学习。不要把三个方向写成同一个算法。

随后读 CHOIS、HIMO、COSMI、HOIFHLI、PrimHOI、World2HOSI。关注它们分别在哪一层组合：数据制造、单个生成器、原语规划或专家调度。完整系统的优势可能来自规划器、专家、条件信息或边界算法，必须拆开比较。

最后以 AMASS/BABEL/HumanML3D、ParaHome、RoboMoCap 等数据来源，以及 Weave/InterMimicGen 等执行工作检查“数据从哪里来”和“生成后能否执行”。舞蹈、手势和视频属于有用的邻近方向；其指标不直接混入完整 3D 交互任务排名。

## 第二轮：逐篇填写输入合同

每篇都问：推理时拿到了什么？

| 条件 | 写作与实验中需要交代 |
|---|---|
| 文本、mesh、初态 | 文本粒度、几何身份、人体/对象/场景初态 |
| 目标与路径 | 用户给定、规划器生成，还是从真实轨迹提取 |
| 时间线与部位区间 | 模型预测还是人工给定；边界与时长是否已知 |
| 供体动作 | 可见的是完整源库片段、过去上下文，还是测试未来 |
| 对象/其他人的运动 | 全未来轨迹、短期计划或已执行历史 |
| GT未来 | 明确列为 oracle 设置，不与实际生成合同混为一谈 |

例如 [OMOMO](papers.md#omomo) 的对象轨迹条件比“文本＋初态”更强；[DecHOI](papers.md#dechoi) 的目标条件与阶段预测路径也应分开记录。更强条件可以是合理任务定义，关键是透明、同条件比较。

## 第三轮：审查组合泛化究竟成立在哪一层

1. **来源重新配对**：不同捕获片段的新组合，首先说明供体配对多样性。
2. **语义组合留出**：整体留出技能语义配对，测试是否重组已学能力。
3. **状态依赖链**：前一步改变的对象位置、支撑或手占用，是否被后一步正确继承。
4. **对象/场景/主体泛化**：分别报告，不以某一种留出替代其他留出。
5. **数据制造收益**：冻结真实独立测试和预算，比较数据加入前后；更多合成序列不自动等于更多独立采集。

源录制、镜像、重采样、裁剪、表示转换与组合后代需要追踪祖先。随机拆片段可能让同一录制进入两边；这是一项要检查的风险，不是对所有论文的默认指控。

## 写 related work 时建议的组织

按“数据与原语组合 → 生成模型的时空/概念组合 → 人物/对象/场景交互 → 长任务与执行 → 组合泛化评价”组织。每段先交代问题和方法谱系，再说明当前问题与已有证据的差别。不要仅按论文年份串名字，也不要根据摘要中没有提到某能力就断言其不支持。

引用用 [references.bib](../references.bib)，与实际阅读版本对应。CoMA 等作品的预印本和正式发表记录存在作者顺序差异，提交论文前应采用目标版本的完整引用。数字结果只有在协议、输入、划分、指标实现与预算一致时才并列表格。

## 下一轮精读优先级

- 为摘要级条目补齐方法章节、输入字段、实际划分与失败案例。
- 为方法级条目补齐确切版本、表格/附录定位和独立可比条件。
- 检查公开实现是否完整，以及默认脚本是否真的对应论文表格。
- 检查组合 benchmark 是否提供时间线、部位职责、目标或 future reference。
- 梳理未覆盖的手语、群体运动与任务运动规划；先判断与当前 survey 范围的关系，再扩展分支。
